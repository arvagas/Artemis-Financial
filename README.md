# Artemis Financial
## Summary
Artemis Financial is a financial institution hiring a consultant who can review and implement best security practices within existing infrastructure. Because the company is handling sensitive information, various requirements must be met, including file verification, vulnerability detection, and secure encryption between server and client devices.

## Final Thoughts
Thoroughly investigating the client's existing codebase to identify the security flaws is an important skill developers should be proficient in. Because a project's dependencies are libraries that are created by third parties, it's essential to be vigilant when it comes to vulnerabilities that can be exploited from such resources. Original code should always be scrutinized, especially when changes are required to align with libraries that have been updated. Keeping the project's code secure not only allows for a more stable program, but also promotes data integrity and prevents malicious actors from attacking potential weak points. This is especially important for companies that deal heavily with sensitive information, such as financial institutions, as a lack of security will only produce negative outcomes, including hurting the brand's reputation, losing customer trust due to exposed information, and economic loss for failed regulatory compliance.

For this project, several measures were implemented to boost security. The cryptographic function SHA-256 was selected for its ability to create unique hash values for validation purposes while adhering to industry standards. Its usefulness in verifying data integrity and generating SSL/TLS certificates to secure web communications is unmatched. Lastly, the OWASP Dependency-Check tool was used to pinpoint vulnerabilities within the project and flag false positives to accelerate future reviews. Lastly, a code walkthrough was conducted at different points to ensure the program was running correctly. Reviewing the codebase at varying points ensures that new features that are implemented do not conflict with current production or cause a new, exploitable bug.

Tools and knowledge that were invaluable during this class include encryption algorithms, Java Keytool for certificate generation, the OWASP Dependency-Check tool, and the use of the National Vulnerability Database to verify known vulnerabilities. I consider these things my current cornerstones of security implementation and can see myself using them frequently in the future when ensuring code is secure. Concerning future employers, I would show the Practices for Secure Software Report, detailing my assessment of the client's requirements and how I would go about implementing security measures before the codebase goes into production.
